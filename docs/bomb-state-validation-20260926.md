フレームゲート、既存ボム入力を使用した。ゲームのPower等の値は書き換えていない。

## 報酬分離への制約

1. 「発動中のダメージを一律0にする」近似は、この状態値を利用可能。
   ボム中に当たったショットも除外される。攻撃元の厳密な分離ではない。
2. 試行bでは発動入力を送った最初の1フレームですでに5 HPのdamageが記録された。
   **遷移前のstateだけで分類すると、発動フレームをショットとして加点する。**
   遷移後だけを見ると終了フレーム中のボム由来ダメージを見逃す可能性がある。
   前後いずれかがactiveならその区間を除外する方法は境界に保守的だが、
   複数フレーム内の全状態を保証しない。イベント発生時点のstate、または各内部フレームの
   active情報を併記するのが次の計測・実装候補。今回はgateの仕様を変えていない。
3. `th10_gate.js` の0x40e1b6/0x40e231イベントは適用ダメージ・撃破を検知するが、
   攻撃オブジェクト／攻撃元は記録しない。`source: verified_game_event` は
   観測の由来であり、ショット／ボムの区分ではない。
4. 終了後90フレームにダメージを観測しなかったが、残存攻撃判定がないことの証明ではない。
   特定の敵配置での2例であり、境界フレームに被弾対象が存在したことや全攻撃判定の寿命は
   独立に確認していない。ショットを90フレーム止めたことも既存弾の完全消滅の証明ではない。
5. ボム終了時のプレイヤー無敵は別状態。両試行とも終了後90フレームの最終ポーズ時にも
   `invincibility_raw=49` が残った。無敵残存をボム発動中と同一視しない。
6. 別キャラ・装備、他面、ボス、死亡・ステージ遷移との同時発動、連続ボム入力、
   低Power空撃ち、未知state値は今回の実機検証範囲外。
