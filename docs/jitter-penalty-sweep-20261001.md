# 往復減点の段階増量

ユーザー依頼: ブレが減るまで減点を増やす。上限-1。改善しないままTanh飽和が悪化する場合は中断可。

実機540更新の同一保存重みから、0.01/0.03/0.1/0.3/1.0を順に比較。各段階3乱数、8192判断、標準32弾幕と難条件32弾幕。実機へ反映しない。判定・学習条件はlive-jitter-trial-20261001.mdと同じ。

停止目安は標準・難条件の両方で、反転回数/秒と12F往復窓率が減点なし対照から20%以上減少し、各課題で3乱数中2以上が両指標で改善すること。性能は別途判定するため、この条件を満たしても即採用はしない。移動距離/秒も測り、静止による見かけの改善を確認。

Tanhは共通の4弾幕から最大16観測を作り、abs(output)>0.99を飽和とする。操作/価値のMLPの両Tanh層を測定。0/0.01/0.03は保存後、0.1以降は各512判断の収集後にも測定。固定小標本による診断であり実プレイ全場面の飽和率ではない。どれかの層が95%以上かつ開始時より5ポイント以上増える状態が3回続けば安全停止フラグを出し、それ以上の減点増加を止める。未到達でも結果から悪化が分かれば判断する。

開始時の価値最終Tanhは71.289%、操作側は0%。減点0.03の学習後は価値最終66.65/66.70/67.97%、操作0%で、増量による飽和悪化はなかった。

実行scripts/sweep_jitter_penalty.py、scripts/jitter_saturation.py。進捗と結果artifacts/live-jitter-trial-20261001/sweep-status.json。

## 飽和
最終モデルを共通観測で再測定: 操作MLPの2層は全seed0%。価値最終Tanhは67.236/64.893/65.674%、開始71.289%より低い。価値前段は15.454/11.743/15.039%。飽和ガードによる中断はなし。今回の標本では増量による飽和悪化は確認されなかった。

追加学習9回×8192判断=73728判断、追加評価3強度×3seed×32弾幕×2開始位置=576試行完了。保存再読み込みの一致/有限値チェック通過。実機へ変更なし。
結論: 前回の-0.001/-0.003では弱すぎた可能性があり、-0.1では狙った往復・反転減少と難条件の回避改善を両立する初期結果を得た。ただし単一実機モデルの重み、短い回避課題、各弾幕1操作乱数の結果であり、実機フル報酬の射撃・進行への影響は未確認。-0.1を有望候補として扱い、実機への自動採用はしない。
