## P専用チャンネル

全体グリッド末尾へ `power_amount` を追加。全体14層・詳細6層。
Pは既存の `item_density` から除外し、それ以外のアイテムは従来の密度表現。

- 小P：Power +0.05。内部type 1と10、raw増加量1。
- 大P：Power +1.00。内部type 4と11、raw増加量20。
- 各8pxマスにraw増加量を加算し、共通倍率100で割る。小P1個は0.01、大P1個は0.2。
- 同じマスの値が1を超えても飽和させない。上限はアイテムプール2198個分の439.6。
- 現在の自機Powerによる取得上限は差し引かず、その位置のPが持つ公称増加量を表す。
- 保存は既存と同じfloat16往復なので量子化誤差はある。
- OBSはPを橙色の濃淡で表示する。表示の不透明度のみ上限1で、モデルのP量は維持。

固定ハッシュの所有ゲームに対する読み取り専用命令照合：
`0x41afd0`でアイテム配列の先頭+0x14、`0x41aff4`でitem+0x3b0をEBPへ。
`0x41b3c1`でEBP+0x30（item+0x3e0）のtypeを読み、type-1で`0x41b8a0`の表へ。
表のtype 1/10は`0x41b3d5`へ分岐（`0x41b04f`のEBX=1を引数にする）。
type 4/11は`0x41b62e`へ分岐（引数0x14）。両方とも`0x418930`を呼び、
`0x418949..0x418963`でPowerへ加算しraw100で上限を適用する。
この調査ではフック追加・ゲーム入力・メモリ書き換えをしていない。

## スペル突破と報酬

進行度報酬を **20 + 30×残機 + 2×Power** に変更。
他の報酬係数はv15のまま。全進行度はボム中0だが到達点を記録し、後から再加点しない。

- Normal・1〜6面の24スペルを対象。
- 最終以外の15スペルは `spell_breakthrough` として、各スペル1回だけ加点。
- 最終9スペルは既存の中ボス／面ボス終了へ統合。独立した加点・グラフ段階は作らない。
- HP条件による突破・時間切れの両方が対象。2面ID19と4面ID50はHPが正の閾値で終了する。
- 自機ゲームオーバー、リトライ、発動フラグの消失だけでは達成扱いしない。
- イベント発生時の残機、Power、ボム状態を使う。

既存の署名検証付き`0x4127a0`終了コールバック解決関数で、発動中スペルのID、
ステージ、ボス役割、返された終了先、HP閾値を照合する。時間切れはflags bit0x10000。
`touhou_ai/spell_progress.json`をPython・Fridaで共有し、既存のECL抽出・参照表とテストで照合。
イベントsourceは`verified_ecl_progress_v2`。以前のv1イベントの読み取りは継続する。

OBS1のグラフではボス登場〜終了の間にスペル段階を挿入し、表示名は一律「スペル突破」。
既存の整数到達点は維持し、途中のスペルはその間の小数rankとする。
最終スペルはボス終了の整数rankだけを記録する。スペル名は表示しない。
